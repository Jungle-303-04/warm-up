# Notion 프로젝트 운영 스킬

## 목적

이 문서는 Notion을 팀 프로젝트 운영 허브로 사용할 때 프로젝트, 회의, 작업을 누락 없이 관리하기 위한 스킬 문서다.

Codex 스킬로 사용할 때는 같은 폴더의 [SKILL.md](./SKILL.md)를 기준으로 한다.

## 운영 DB 기준

| DB | 의미 | 작성 기준 |
|---|---|---|
| 프로젝트 | 큰 목표 단위 | 기간, 담당자, 참여자, 관련 회의, 관련 작업을 연결 |
| 회의 | 논의와 결정의 출처 | 회의 날짜, 참석자, 결정 사항, 후속 조치를 기록 |
| 작업 | 담당자가 실행할 수 있는 일감 | 담당자, 기간, 상태, 프로젝트, 관련 회의를 연결 |

일정은 별도 DB로 늘리지 않는다.
프로젝트 기간, 회의 날짜, 작업 기간으로 본다.

## 구현 기록 기준

코드 구현을 프로젝트나 작업으로 옮길 때는 파일 목록보다 실제 동작을 먼저 적는다.

| 구분 | 먼저 쓸 내용 | 보조로 쓸 내용 |
|---|---|---|
| 프로젝트 | 목표, 구현된 동작, 파이프라인 흐름, 검증 결과, 관련 커밋 | 관련 파일 |
| 작업 | 목표, 실제 구현, 동작 확인, 완료 기준 | 관련 파일 |

파일 경로만 나열한 작업은 만들지 않는다.
관련 파일은 본문 마지막의 보조 정보로만 둔다.
상대 날짜는 절대 날짜로 확정한다. 예를 들어 2026-06-10에 "내일까지"라고 하면 기간은 2026-06-10부터 2026-06-11까지다.

## 상태 기준

| 상태 | 의미 |
|---|---|
| 시작하지 않음 | 아직 시작하지 않음 |
| 진행 중 | 담당자가 실행 중 |
| 보류 중 | 외부 조건 때문에 멈춤 |
| 완료 | 완료 또는 종료됨 |

## 회의 운영 흐름

```text
회의 생성
-> 논의 내용 기록
-> 결정사항 정리
-> 실행 항목을 작업으로 분리
-> 담당자와 기간 입력
-> 관련 프로젝트와 회의 연결
-> 완료 상태로 닫기
```
